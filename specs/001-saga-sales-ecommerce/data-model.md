# Data Model: Saga-Sales E-Commerce Platform

*Phase 1 output of `/speckit-plan` — **dialect: SQL Server 2022 / T-SQL***

Implements the entities of [`spec.md`](./spec.md) under the persistence rules of
[`research.md`](./research.md) R1, R2, R5 and R6, corrected to SQL Server by decision **D11**.

---

## 1. Databases

One SQL Server 2022 instance, one database per service, no cross-database query.

| Service | Database | Owner of |
|---|---|---|
| Identity | `saga_identity` | tenants, users |
| Catalog | `saga_catalog` | products, prices, categories, stock |
| Sales | `saga_sales` | orders, order lines |
| Payment | `saga_payment` | payments, order references |
| Customer | `saga_customer` | customers, addresses |
| Analytics | `saga_analytics` | daily aggregates |
| Notification | `saga_notification` | notification logs, templates |

Every database carries, as the first statement of `V001__schema.sql`:

```sql
IF OBJECT_ID('dbo.schema_version') IS NULL
CREATE TABLE dbo.schema_version (
    version    int           NOT NULL PRIMARY KEY,
    script     nvarchar(200) NOT NULL,
    applied_at datetime2(3)  NOT NULL CONSTRAINT df_schema_version_applied DEFAULT SYSUTCDATETIME()
);
```

`scripts/apply-db.ps1` creates the database when missing, applies `V###__*.sql` in order with
`sqlcmd -b`, and records each version. Re-running skips what is already recorded.

## 2. Conventions

1. **Tenant first**: every procedure that touches business data takes **`@p_tenant_id uniqueidentifier`**
   as its first parameter and filters on it. There is no procedure that reads across tenants.
2. **Identifiers**: `uniqueidentifier`, generated by the application (`NEWID()` only for seed data).
3. **Money**: `decimal(18,2)`. Never `float`. Currency is fixed to `USD` (D6) and enforced with a
   `CHECK` constraint.
4. **Timestamps**: `datetime2(3)`, always UTC (`SYSUTCDATETIME()`).
5. **Soft delete**: a status column, never `DELETE`, for products, customers and orders.
6. **Enums**: `smallint` with a `CHECK` constraint listing the allowed codes, so the database rejects
   an invalid state even if a handler is wrong.
7. **JSON**: `nvarchar(max)` with `CHECK (ISJSON(column) = 1)` where a document is stored.
8. **Errors**: procedures signal domain failures with
   `THROW 50000, 'CODE: message', 1;` — the code is the message prefix, which
   `SqlErrorMapper` turns into an HTTP status. Known codes: `NOT_FOUND`, `CONFLICT`,
   `INSUFFICIENT_STOCK`, `INVALID_TRANSITION`, `PAYMENT_ALREADY_EXISTS`,
   `REFUND_EXCEEDS_REFUNDABLE`, `VALIDATION_ERROR`.
9. **Transactions**: multi-table writes use
   `SET XACT_ABORT ON; BEGIN TRAN … BEGIN TRY … COMMIT … END TRY BEGIN CATCH IF @@TRANCOUNT > 0 ROLLBACK; THROW; END CATCH`.
10. **Locking**: `WITH (UPDLOCK, ROWLOCK)` on the row read before an update that depends on its value.
11. **Shape**: procedures `SELECT` the result set and the caller uses `CommandType.StoredProcedure`;
    no output parameters for data.

Indexes: `(tenant_id, name)`, `(tenant_id, status)`, `(tenant_id, category_id)`.

### dbo.product_prices (D5)

`id`, `tenant_id`, `product_id` FK, `customer_type smallint CHECK (1,2)`, `price decimal(18,2) CHECK > 0`.
`UNIQUE (tenant_id, product_id, customer_type)`. Absence of a row means *no specific price*: the base

### dbo.categories

`id`, `tenant_id`, `name nvarchar(100)`, `slug nvarchar(120)`, `parent_id uniqueidentifier null`.
`UNIQUE (tenant_id, name)`, `UNIQUE (tenant_id, slug)`.

### Procedures

| Procedure | Rule |
|---|---|
| `sp_product_create` / `sp_product_update` | returns the row |
| `sp_product_retire` | status → discontinued, never deletes (FR-010) |
| `sp_product_get` | |
| `sp_product_list` | filters (category, search) **before** paging; returns rows plus `total_count` |
| `sp_price_set` | upsert with `MERGE` |
| `sp_price_resolve` | returns `price` and `source` (`base` \| `list`) — the fallback is explicit (FR-007b) |
| `sp_stock_reserve` | `SELECT … WITH (UPDLOCK, ROWLOCK)`; raises `INSUFFICIENT_STOCK` |
| `sp_stock_release` | compensation (FR-014) |
| `sp_category_create` / `sp_category_list` | unique name per tenant |

Example of the locking rule:

```sql
CREATE PROCEDURE dbo.sp_stock_reserve
    @p_tenant_id uniqueidentifier,
    @product_id  uniqueidentifier,
    @quantity    int
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;
    BEGIN TRAN;

    DECLARE @stock int, @name nvarchar(255);

    SELECT @stock = stock_quantity, @name = name
    FROM dbo.products WITH (UPDLOCK, ROWLOCK)
    WHERE id = @product_id AND tenant_id = @p_tenant_id AND status = 2;

    IF @stock IS NULL
    BEGIN
        ROLLBACK;
        THROW 50000, 'NOT_FOUND: product does not exist for this tenant', 1;
    END

    IF @stock < @quantity
    BEGIN
        ROLLBACK;
        THROW 50000, 'INSUFFICIENT_STOCK: not enough units available', 1;
    END

    UPDATE dbo.products
    SET stock_quantity = stock_quantity - @quantity,
        updated_at = SYSUTCDATETIME()
    WHERE id = @product_id AND tenant_id = @p_tenant_id;

    COMMIT;
END
```

### State machine (FR-013)

```
pending(1) → confirmed(2) → processing(3) → shipped(4) → delivered(5) → refunded(7)
pending/confirmed/processing → cancelled(6)          (final)
```

Enforced by `sp_order_change_status`, which throws `INVALID_TRANSITION` for anything else.

### Procedures

| Procedure | Rule |
|---|---|
| `sp_order_create` | one transaction over header and lines; lines carry the snapshot (FR-012) |
| `sp_order_get` / `sp_order_list` | |
| `sp_order_change_status` | validates the transition |
| `sp_order_register_payment` | adds to `paid_amount`, confirms a pending order |

## 10. Validation rules and where they are enforced

| Rule | Enforced in |
|---|---|
| Product name ≥ 2 chars, price > 0, stock ≥ 0 | FluentValidation **and** `CHECK` constraint |
| Currency is USD | `CHECK (currency = 'USD')` |
| Category name unique per tenant | unique index |
| Customer email unique per tenant | unique index |
| Stock never negative | `CHECK (stock_quantity >= 0)` |
| Refund never exceeds refundable | `CHECK (refunded_amount <= amount)` + procedure guard |
| Order status transitions | `sp_order_change_status` |
| One live payment per order | `sp_payment_create_manual` |
| Tenant always present | first parameter of every procedure |
| Shipping address required | `orders.shipping_address NOT NULL` |
| JSON columns are valid JSON | `CHECK (ISJSON(...) = 1)` |
